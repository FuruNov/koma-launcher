# 自分の画像でコマ割りを作る

形式の全体は `docs/layout-json.md` の「インポート用のフォルダ」と「version 2」にある。ここでは作業の順番と、間違えやすい所を書く。

画像は利用者のもの。リポジトリの `art/`（`.gitignore` にある）か、リポジトリの外に置き、コミットしない。

## 1. どちらの方法で作るか決める

- **端末の編集画面で作る**: コマの分割・画像の選択・位置合わせは、ホームの余白を長押しして「コマ割りを編集」から行える。切り抜きを使わないなら、これだけで足りる。ただし、端末のギャラリーから選んだ画像はバックアップに含まれない。
- **layout.json を書いて送る**: 画像と切り抜きをまとめて追加したいとき、同じコマ割りを別の端末にも適用したいときに使う。以下はこの方法。

## 2. 画像をそろえる

- 名前は英数字とハイフンにする（例: `pic-1`）。`art.image` にはこの名前を拡張子なしで書く。
- 形式は jpg・jpeg・png・webp。アプリが長辺 2048 以下に縮めて webp で保存するので、元の大きさは気にしなくてよい。
- コマより縦横比が大きく外れる画像は、`zoom` を上げないと端が見えてしまう。アプリは絵の端をコマに見せない範囲に `zoom`・`dx`・`dy` を収める。

## 3. layout.json を書く

コマ割りは、コマを線で 2 つに割ることを繰り返した木で書く。最小の例:

```json
{ "version": 2,
  "frame": { "refWidth": 1220, "margin": 24, "gutter": 18, "bleed": false,
             "border": { "style": "single", "width": 10, "color": "#111111" } },
  "tree": { "cut": { "ta": 0.30, "tb": 0.80 },
            "a": { "panel": { "id": "fav", "kind": "folder", "label": "よく使う",
                              "art": { "image": "pic-1" } } },
            "b": { "panel": { "id": "all", "kind": "drawer", "label": "その他",
                              "art": { "image": "pic-2" } } } } }
```

- `ta`・`tb` は線の両端の位置で、親のコマの周の長さに対する割合（左上の頂点から時計回りに 0〜1）。辺の長さに比例するので、縦長の画面では上の辺が短い。1220×2712 の画面全体なら、上の辺が 0〜0.155、右の辺が 0.155〜0.5、下の辺が 0.5〜0.655、左の辺が 0.655〜1 になる。上の例の 0.30 は右の辺の上から 4 割ほど、0.80 は左の辺の下から 4 割ほどの所で、線は右上から左下へ少し傾いて画面を上下に分ける。
- `a` は線の進む向きの左側のコマ、`b` が右側。思った向きにならなければ、`a` と `b` を入れ替える。
- `id` はコマごとに一意にする。後で `id` を変えると、そのコマのフォルダの中身は「割り当てのないアプリ」に移る。
- `apps` は初回だけフォルダに追加する初期値。利用者の端末にインストール済みのアプリのパッケージ名は `adb shell pm list packages -3` で調べる。
- 書いたら、`:core:model` のパーサーで確認できる。`LayoutV2ParserTest.kt` に一時的なテストを書いて `LayoutParser.parse` に渡すか、端末に送って上端にエラーが表示されないかを見る。壊れた `layout.json` を送っても、前のレイアウトとフォルダの割り当ては消えない。

細かい位置は、送った後に端末の編集画面と「配置を調整」で合わせるほうが早い。合わせた結果は、設定画面の「自動バックアップ」で選んだフォルダの `koma-launcher-backup.json` に入る。

## 4. 人物の切り抜きを作る（任意）

切り抜きがあると、コマの名前・大見出し・時計を人物の後ろに描き、立体感の効果（`docs/layout-json.md` の `depth`）を使える。端末の中では作らない（イラストの輪郭が粗かったため、ML Kit は外した）。PC で BiRefNet を使う。

- 出力は、元の画像と同じ縦横比のグレースケールの PNG で、白が人物、黒が背景。アプリは濃さ 0.35〜0.65 を 0〜1 に詰めて使うので、中間の灰色は少なくてよい。
- BiRefNet は Hugging Face の `ZhengPeng7/BiRefNet` を `transformers` の `AutoModelForImageSegmentation.from_pretrained(..., trust_remote_code=True)` で読める。使い方はモデルのページの例に従う。Python の環境は利用者に確認してから作る。
- 白と黒が逆の画像（白が人物以外）を作ったなら、`inv` として置く。

## 5. 端末に転送する

置く場所の名前は、方法によって違う。

| 方法 | 画像 | 白が人物の切り抜き | 白が人物以外の切り抜き |
|---|---|---|---|
| adb でインポート用のフォルダへ | `art/<名前>.<拡張子>` | `art/<名前>.mask.png` | `art/<名前>.inv.png` |
| 設定画面の「フォルダから復元」 | `<名前>.<拡張子>`（`art/` の下でもよい） | `mask/<名前>.png` | `inv/<名前>.png` |

**adb**（インポート用のフォルダは `/sdcard/Android/data/dev.furunov.komalauncher/files/`）。画像と切り抜きを先に、`layout.json` を最後に送る。アプリは `layout.json` が置かれたときにインポートを始めるため。

```sh
D=/sdcard/Android/data/dev.furunov.komalauncher/files
adb shell mkdir -p $D/art
adb push art/mine/pic-1.jpg art/mine/pic-1.mask.png $D/art/
adb push art/mine/layout.json $D/
adb shell ls $D    # layout.json.imported に名前が変わればインポートできた
```

**フォルダから復元**: 上の表の形でフォルダを作り、pCloud などのクラウドか端末の共有ストレージに置く。設定画面の「フォルダから復元」でそのフォルダを選ぶ。adb が無い利用者にはこちらを勧める。

## 6. 確認する

ホームに戻り、各コマに画像が表示されること、切り抜きを置いたコマで名前が人物の後ろに隠れることを見る。画像が表示されないときは、`art.image` の名前と、置いたファイルの名前（拡張子を除く）が一致しているかを確認する。
