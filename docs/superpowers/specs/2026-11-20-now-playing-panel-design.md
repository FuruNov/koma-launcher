# 音楽の再生中にコマをプレイヤーにする（設計）

2026-11-20 に利用者と決めた内容。モックアップは claude.ai の Artifact で作った。利用者は第 3 版の見せ方 E（ジャケットと、下の辺の棒のビジュアライザー）を選んだ。曲名は表示しない。

## 目的

利用者は、音楽を流しながらホームに戻ったときに、今の曲をコマで見たい。同時に、ホームから再生・一時停止・曲送りもしたい。見た目と操作の両方を重視する。

ふだんはフォルダとして使っているコマを、音楽が再生中か一時停止中のあいだだけプレイヤーの表示に切り替える。再生していないときは、いつものコマに戻る。

## 対象外・避けること

- 新しいコマの種類（`kind`）は追加しない。フォルダのコマに付ける設定にする。
- ボタンや操作の帯は置かない（モックアップの B は採用しなかった）。操作はタップとジェスチャーだけにする。
- 曲の一覧、キュー、シーク、音量の操作は作らない。
- 曲名・アーティスト名は表示しない（利用者が決めた）。
- 回転するディスクは作らない（ビジュアライザーを採用した）。
- 通知の吹き出し表示は、同じ許可を使うが今回は作らない。
- ホームを表示していない間に再生状態を監視し続けない（電池を減らさない）。

## 表示（見せ方 E）

対象のコマが「プレイヤー表示」になるのは、再生中のセッションがあり、その状態が再生中・一時停止中・読み込み中のどれかのとき。停止・エラー・セッションなしなら、いつものコマを表示する。

一時停止から一定の時間（既定は 30 分）が過ぎたら、セッションが残っていても、いつものコマに戻す。音楽アプリは一時停止のあとも何時間もセッションを残すことがあり、その間ずっとタップが再生・一時停止になるのを避けるため（利用者が決めた）。再生を再開すれば、またプレイヤー表示になる。この時間は設定画面で変えられるようにする。一時停止になった時刻は、ランチャーが状態の変化を受け取った時刻で数える（ホームが前面にない間の一時停止は、前面に戻ったときに受け取った `PlaybackState` の更新時刻を使う）。

プレイヤー表示のときは、次のように表示する。

- コマの絵の代わりに、ジャケット画像をコマいっぱいに cover で表示する（今のコマの絵と同じ切り抜き方）。コマごとの位置合わせ（zoom・dx・dy）と暗さ（`art.dim`）は適用しない。人物の切り抜きも使わない。
- コマの名前は表示しない。曲名も表示しない。時計と大見出しは、今の描画のとおり表示する。
- コマの下の辺に沿って、ビジュアライザーの棒を並べる（下記）。
- 一時停止中は、ジャケットを残したまま彩度と明るさを下げ、コマの中央に再生の記号を表示する。棒は 0 へなめらかに下がって止まる。
- 曲が変わったら、ジャケットを 250ms 程度でクロスフェードする。
- ジャケット画像がない曲は、コマの元の絵の上に棒を表示する。
- 進み具合は表示しない（実装者の判断。下の辺は棒が使う）。

```
┌───────────────┐
│               │
│  ジャケット    │
│ （コマいっぱい）│
│               │
│ ▌ ▌▌  ▌      │
│▌▌▌▌▌▌▌▌▌ ▌▌ ▌│ ← 下の辺から立つ棒
└───────────────┘
```

## ビジュアライザー

### 棒の並べ方

- 「下の辺」は、コマの多角形の辺のうち、中点の y が最も大きい（画面の下にある）辺とする。辺が斜めなら、棒も辺に垂直に立てる（モックアップと同じ）。
- 棒の数は辺の長さで決める（モックアップでは 9dp ごとに 1 本、最低 10 本）。左から低い音、右に高い音を並べる。
- 棒の高さの上限は、コマに収まる最大の長方形の高さの半分程度とする。棒はコマの多角形で切り抜く。
- 色はドラッグ時の強調色（設定の `highlightColor`）で、値が大きいほど不透明にする。

### 値の取得

棒の値（0〜1 の並び）を返す取得元をインターフェースにし、2 つの実装を置く。

1. **実際の音**: `android.media.audiofx.Visualizer` を出力全体（セッション 0）に付け、FFT を受け取る。周波数を対数の間隔で棒の数にまとめ、上がるときは速く、下がるときはゆっくり動かす。マイクの権限（`RECORD_AUDIO`）が必要。
2. **それらしい動き**: 再生中だけ、拍と揺らぎで作った値を返す（モックアップと同じ）。権限は不要。

選び方は次のとおり。

- マイクの権限があり、`Visualizer` を作れたら 1 を使う。再生中なのに値が 5 秒続けてすべて 0 なら、その端末やアプリでは取得できないとみなし、2 に切り替える。
- 権限がない、または `Visualizer` を作れなければ 2 を使う。
- 1 が実機（POCO X7 Pro、HyperOS、YT Music）で動くかはまだ確かめていない。利用者が PC の前に戻ってから確かめる。それまでは 2 で全体を完成させ、1 は実装したうえで、設定画面の切り替え（下記）でオンにしたときだけ使う。

### 権限（マイク）

- 設定画面の「音楽プレイヤー」の欄に「音に合わせて動かす」の切り替えを置く。オンにしたときにマイクの権限を求める。説明の文に「音を録音・保存はしない。Android の仕組み上、音の波形を受け取るのにこの許可が必要」と書く。
- 権限を断られたら、切り替えをオフに戻し、2 の動きを使う。

### 描画と電池

- ホームが前面にあり、プレイヤー表示で、再生中のときだけ描き直す。一時停止して棒が 0 まで下がったら描き直しを止める。
- `Visualizer` は、ホームが前面にあり再生中のときだけ有効にし、それ以外は解放する。
- 描き直しはフレームごと（`withFrameNanos`）でよい。電池の消費が気になれば、後で 30fps に落とす。

## 操作

プレイヤー表示のコマの上だけで、次のように操作する。

| 操作 | 動作 |
|---|---|
| タップ | 再生・一時停止の切り替え |
| 左へスワイプ | 次の曲 |
| 右へスワイプ | 前の曲 |
| 長押し | コマのメニュー（下記） |

- 操作したときは、コマの中央に再生・一時停止・曲送りの記号を 0.6 秒ほど表示して消す（モックアップと同じ）。
- 上下のスワイプは、今と同じく画面全体のジェスチャー（全アプリ一覧・通知センターなど）に使う。左右のスワイプは今どこにも割り当てていないので、ぶつからない。
- プレイヤー表示でないとき、このコマは今のフォルダと同じ動作をする（直接起動がオンなら先頭のアプリを起動）。

### コマの長押しのメニュー

フォルダのコマのメニューに、次の項目を追加する。

- 「音楽プレイヤー: オン／オフ」: このコマをプレイヤー表示の対象にするかを切り替える。対象にできるコマは 1 つだけで、別のコマをオンにすると前のコマはオフになる。
- プレイヤー表示の間は「フォルダを開く」と「再生中のアプリを開く」も表示する。タップが再生・一時停止に変わるので、フォルダへの入口をここに置く（直接起動のときと同じ考え方）。

## 権限（通知へのアクセス）

- アプリに `NotificationListenerService` を 1 つ追加する（中身は空でよい。許可の対象として必要）。再生状態は `MediaSessionManager.getActiveSessions(そのコンポーネント)` で取得する。
- 「音楽プレイヤー: オン」にしたときに許可がなければ、短い説明を表示してから Android の「通知へのアクセス」の設定画面を開く。許可がない間は、オンにしたコマもいつものコマのまま表示する。
- 設定画面に「音楽プレイヤー」の項目を追加し、許可の状態（許可済み・未許可）を表示する。押すと同じ設定画面を開く。
- 実機には GitHub Release の APK をブラウザ経由で入れている。Android 13 以降では、この方法で入れたアプリの「通知へのアクセス」は「制限付き設定」になり、そのままでは許可できないことがある（実装者の判断で対応する）。説明の文に「許可できないときは、アプリ情報の右上のメニューから『制限付き設定を許可』を選ぶ」と書き、アプリ情報の画面を開くボタンも置く。

## 再生状態の取得

- ホームが前面にある間（ライフサイクルが STARTED 以上）だけ、`OnActiveSessionsChangedListener` とセッションの `MediaController.Callback` を登録する。前面から外れたら解除する。
- 対象のセッションは、`getActiveSessions` が返す順（Android が優先度の順に返す）に見て、状態が再生中・一時停止中・読み込み中の最初のもの（実装者の判断）。先頭が停止したアプリでも、2 番目が一時停止中ならそれを使う。そのため、`MediaController.Callback` は有効なセッションすべてに登録する。
- 再生位置は `PlaybackState` の位置・更新時刻・速度から計算し、表示は 1 秒ごとに更新する。
- ジャケット画像は、メタデータの画像（ART、ALBUM_ART）を使い、なければ URI（ART_URI、ALBUM_ART_URI）から読む。コマの大きさに合わせて縮小してから持つ。
- 再生・一時停止・曲送りは `MediaController.transportControls` で送る。

## 対象外のレイアウト

version 1（1 枚の絵）のレイアウトでは、プレイヤー表示を行わない（実装者の判断）。

## 構成

今のモジュールの分け方に合わせる。

- `:core:model`: 再生状態の型（状態・パッケージ名など。画像は含めない）と、取得・操作のインターフェース。プレイヤー表示にするかの判定、下の辺の選び方、FFT を棒の値にまとめる計算、それらしい動きの値の計算は、ここに純粋な関数で書いてテストする。設定に「一時停止から元に戻すまでの時間」と「音に合わせて動かす」を追加する。フォルダの設定に「音楽プレイヤー」の真偽値を追加し、1 つだけオンにする編集の関数を追加する（`FolderEdits.setDirectLaunch` と同じ形）。
- `:core:platform`: `MediaSessionManager` を使う実装、`NotificationListenerService`、ジャケット画像の読み込み、`Visualizer` を使う実装。
- `:feature:home`: プレイヤー表示の描画、タップとスワイプの振り分け、長押しのメニュー。
- `:feature:settings`: 「音楽プレイヤー」の欄（通知へのアクセスの状態、一時停止から元に戻すまでの時間、音に合わせて動かす）。
- フォルダの設定は folders.json に保存されるので、バックアップにも含まれる。古い folders.json は、項目がなければオフとして読む。

## テスト

- `:core:model` の単体テスト: プレイヤー表示にする条件（一時停止からの経過時間を含む）、下の辺の選び方、FFT のまとめ方、1 つだけオンにする編集、古い folders.json と設定の読み込み。
- `HomeViewModel` のテスト: プレイヤー表示のコマのタップ・スワイプが再生の操作に変わること、表示でないときはフォルダの動作に戻ること。
- Waydroid で手で確かめる: YT Music での表示と操作、一時停止、曲の切り替え、許可の取り消し。
- 実機（POCO X7 Pro）では、利用者が戻ってから確かめる: 上と同じ項目に加え、`Visualizer` が値を返すか、HyperOS での動作。

## 実装者に任せること

- 棒の太さ・間隔・なめらかさの係数。
- 一時停止中の彩度と明るさの値（`ToneMatrix` で作れる）。
- 記号の形とアニメーションの細部。
- ジャケット画像の縮小の大きさと、キャッシュの持ち方。
- スワイプと判定する距離（今の画面全体のスワイプの判定に合わせる）。
