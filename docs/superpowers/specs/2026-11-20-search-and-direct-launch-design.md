# 検索の改善、押すと直接起動するコマ、コマの背景を暗くする（設計）

2026-11-20 に利用者と決めた内容。

## 目的

利用者は、ホーム画面のアイコンが増えすぎて目的のアプリを探すのが大変だと感じている。ホームに置くアプリを少数に絞り、それ以外は名前を打って開けるようにする。

- 毎日使う数個のアプリは、押すとすぐ起動するコマに置く。
- 用途ごとにまとめたいアプリは、今と同じフォルダに入れる。
- 残りのアプリは、全アプリ一覧の検索から開く。検索がいちばん多く使う入口になるので、検索までの手数と、少ない文字数で目的のアプリが先頭に来ることを重視する。

## 対象外

- 一致するアプリが無いときの Web 検索（狙いから外れる）。
- 長く使っていないアプリの通知（起動回数の記録が溜まってから検討する）。
- アプリの別名（漢字の名前の読みの代わり）。必要になったら後で追加する。
- アイコンの並び、色、検索欄の位置の変更。

## 検索

### 画面

- 全アプリ一覧を開いた時点でキーボードを表示する。
- 入力が空のとき: 上に「よく使う」の 1 行（起動回数の多い順に、列の数だけ）、その下に今と同じ名前の順の全アプリ。
- 入力があるとき: アプリを点数の高い順に並べ、先頭を枠で囲む。一致した文字を太字にする。その下に「ショートカット」の見出しと、アイコン・「アプリ名 · 項目名」の行を点数の順に並べる。
- Enter で先頭のアプリを起動する。アプリが 1 つも一致せずショートカットが一致したら、先頭のショートカットを起動する。

```
┌──────────────────────────────┐
│ [ gm|                 ]  設定 │
│ ┏━━━━━━┓                      │
│ ┃Gmail ┃  Google Maps          │
│ ┗━━━━━━┛                      │
│ ショートカット                 │
│  ✉ Gmail · 新規作成            │
│ ┌ キーボード ───────────────┐ │
└─┴───────────────────────────┴─┘
```

### 照合（`:core:model` の純粋な関数）

- fzf と同じく、入力の文字が順番どおりに含まれていれば一致とする。点数は、名前の先頭での一致、単語の頭（空白・記号・大文字の直後）での一致、連続した一致に加点し、一致の間が空くと減点する。同点なら起動回数の多い順、それも同じなら名前の順。
- 名前と入力の両方を正規化してから照合する。全角英数を半角に、大文字を小文字に、カタカナをひらがなにそろえる。
- 入力がローマ字なら、ひらがなに変換した入力でも照合し、点数の高いほうを採用する。変換表は自前で持つ。
- パッケージ名の最後の部分（`com.android.settings` の `settings`）も照合の対象にする。名前より点数を下げる。漢字の名前のアプリを英語で探せるようにするため。
- 一致した文字の位置を返し、画面はそれを太字にする。

### 起動回数

- `AppCatalog.launch` を通る起動（一覧・フォルダ・コマ・ジェスチャー）を数える。回数はアプリの内部の JSON（`JsonFileStore`）に保存し、端末の外には送らない。
- ショートカットの起動は数えない。

### ショートカット

- `AppCatalog.shortcuts` はアプリごとに問い合わせる形なので、検索用には全アプリの分をまとめて取得して持っておく。一覧を開いたときに取得し、入力のたびには問い合わせない。ホームアプリに設定されていないときは空になる（今と同じ）。

## 押すと直接起動するコマ

### 検討した方法

| 方法 | 内容 | 判断 |
|---|---|---|
| A. コマの種類に「アプリ」を作る | 編集画面で起動するアプリを選ぶ | 割り当てが `layout.json` に入り、コマ割りと割り当てを分ける今の方針に反する。モックアップの取り込みで上書きされるおそれもある。変更が最も大きい |
| B. アプリが 1 つだけのフォルダは直接起動する | ルールを 1 つ加える | 中身の数で動きが暗黙に変わる。今ある 1 アプリのフォルダも更新直後から動きが変わる |
| **C. フォルダに「押したら直接起動」の切り替えを付ける** | 長押しメニューで切り替える | **採用**。動きを利用者が明示的に選べ、割り当ては `folders.json` のまま、ドラッグ＆ドロップもそのまま使える |

### 内容

- `Folder` に `directLaunch: Boolean = false` を加える（`folders.json` の既存のファイルはそのまま読める）。
- コマの長押しメニュー（フォルダのコマだけ）に「押したら直接起動」の切り替えと「フォルダを開く」を加える。
- 切り替えがオンのフォルダのコマを押すと、押したときのアニメーションの後、フォルダを開かずに先頭のアプリを起動する。フォルダが空なら今までどおりフォルダを開く。
- ドラッグ＆ドロップでアプリをこのコマへ運ぶ操作は今までどおり。先頭のアプリを替えるには、「フォルダを開く」で開いて並べ替える。
- 設定画面のジェスチャーの「フォルダを開く」は、切り替えに関係なくフォルダを開く。

## コマの背景を暗くする

利用者は Y!天気の天気予報のウィジェットを常用し、YT Music のプレイヤーも見た目がよいので置いている。Y!天気のウィジェットは背景の透過率を 0〜100% で設定でき、透過させると明るい絵の上で白い文字が読みにくくなる。YT Music のウィジェットは不透明なので、この機能の対象ではない。

- `PanelArt` に `dim`（0〜1、既定 0）を加え、`layout.json` の `art` に `"dim"` として読み書きする。省けば 0。
- 絵を描いた後、内側の影・光の反射・枠線より前に、コマの形で黒（不透明度 = `dim`）を重ねる。
- 編集画面では、画像の位置合わせと同じ場所に「暗さ」のスライダーを 1 本置く。どの種類のコマでも使える。
- 実際のウィジェットでの見た目は、Waydroid に入れた Y!天気で確かめる（利用者が初回の案内と利用規約への同意を済ませた後）。

## 確認の方法

- 照合の関数と、起動回数による並べ替えは単体テストで確かめる（ローマ字・カタカナ・パッケージ名の例を含める）。
- 直接起動は `HomeViewModelTest` で確かめる。
- Waydroid の e2e に、検索して Enter で起動する操作と、直接起動のコマの操作を加え、スクリーンショットで画面を確かめる。
- サブエージェントのコードレビューは、このセッションで追加する機能をすべて終えた後に 1 回だけ頼む。

## 実装する人に任せること

- 点数の具体的な値（加点・減点の大きさ）。上の例（「gm」で Gmail が先頭、「rain」と「らいん」で LINE）が成り立つように決める。
- ショートカットをまとめて取得する方法（パッケージを指定しない問い合わせが使えるか、アプリごとに問い合わせるか）。
- 起動回数の保存の形と、数え方（単純な回数か、古い起動の重みを下げるか）。
