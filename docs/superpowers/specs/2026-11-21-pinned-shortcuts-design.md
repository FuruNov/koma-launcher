# ホーム画面へのショートカットの追加（固定したショートカット）の設計

2026-11-21 に利用者と決めた内容。

## 目的

利用者は、Vivaldi で PWA（アイマスイントロアプリ、paper-catch-up など）を「ホーム画面に追加」したい。Chrome 以外のブラウザは PWA を WebAPK（独立したアプリ）にせず、Android の固定したショートカット（`ShortcutManager.requestPinShortcut`）として既定のホームアプリに置いてもらう。今の koma-launcher はこの依頼を受け付けないので、追加できない。

固定したショートカットは PWA 以外にもある（普通のウェブページの「ホーム画面に追加」、連絡先の「ホーム画面に追加」など）。どれも同じ仕組みで受け付ける。

PWA の追加はときどき行う程度と見込む。受け付けた後の操作は、確認と置き場所の選択の 1 画面で済ませる。

## 目標

- ブラウザなどからの固定の依頼を受け付け、アイコンと名前を確かめて追加できる。
- 追加したショートカットを、アプリと同じように扱える。全アプリ一覧と検索に名前とアイコンで並び、フォルダに入れ、並べ替え、コマ間で移し、直接起動の先頭にでき、コマのアイコンにも表示される。
- 起動すると、ほかのランチャーから起動したときと同じ画面が開く。PWA なら、ブラウザのタブではなく PWA の画面で開く。
- 長押しのメニューから削除（固定の解除）できる。

## 対象外

- ウィジェットの追加の依頼（`ACTION_CONFIRM_PIN_APPWIDGET`）。同じ仕組みで後から追加できるが、今回は作らない。
- 仕事用プロファイルのショートカット（今のアプリ一覧も扱っていない）。
- ショートカットの名前やアイコンの変更。

## 避けたいこと

- **PWA がブラウザのタブで開くこと。** ショートカットから URL を取り出して開く作りにしない。必ずショートカットの id で `LauncherApps.startShortcut` を呼び、ブラウザが作った起動の命令をそのまま使う。Chromium 系のブラウザは、命令に含めた検証の値で、他のアプリが勝手に PWA の画面を開けないようにしている（私の知識による。実機で確かめる）。
- 画面の上で「ショートカット」という言葉を使うこと。利用者には、追加したものはアプリと同じに見える。
- 既存の `folders.json`・`launches.json`・バックアップが読めなくなること。

## 案と選んだもの

1. **ショートカットをアプリと同じ扱いにする（採用）。** アプリの識別子 `AppKey` に、省略できる `shortcutId` を追加する。固定したショートカットは、アプリ一覧（`AppCatalog.apps`）に `AppEntry` として並べる。フォルダ・ドラッグ・直接起動・コマのアイコン・バックアップは `AppKey` で動いているので、そのまま使える。分岐が要るのは、起動・アイコンの読み込み・長押しのメニュー・起動回数の id だけ。
2. フォルダの中身を「アプリかショートカット」の 2 種類にする。データの形としては素直だが、フォルダの処理の全てを 2 種類に対応させる必要があり、利用者から見て 1 より良くなる点が無い。
3. フォルダとは別にショートカットの欄を持つ。アプリとの並べ替えやコマ間の移動ができず、一覧と検索にも出ない。

利用者は 1 を選んだ。

## 設計

### データ

`core/model/.../model/apps/Apps.kt` の `AppKey` に項目を追加する。

```kotlin
@Serializable
data class AppKey(
    val packageName: String,
    val className: String,
    /** 固定したショートカットなら、その id。null ならアプリ（Activity）。 */
    val shortcutId: String? = null,
)
```

- ショートカットの `AppKey` は、`packageName` が作ったアプリ（Vivaldi なら Vivaldi のパッケージ）、`className` が空文字列、`shortcutId` が id。
- 既定値が null なので、既存の `folders.json` とバックアップはそのまま読める。保存の Json は `ignoreUnknownKeys = true` なので、古い版で新しいファイルを読んでも失敗しない（古い版では、ショートカットはパッケージ名だけの、押しても起動しないタイルになる。古い版に戻すことは想定しないので、対応しない）。
- 起動回数（`Launches.kt`）の id は今 `パッケージ/クラス`。ショートカットは `パッケージ/@id` にする。クラス名は `@` で始まらないので、`parseId` で区別できる。

### 一覧（`LauncherAppsCatalog`）

- `reload()` で、Activity の一覧に加えて、固定したショートカットを `ShortcutQuery().setQueryFlags(FLAG_MATCH_PINNED)` で取得し、`isEnabled` のものだけを `AppEntry(AppKey(pkg, "", id), shortLabel ?: longLabel ?: id)` として加える。並びはラベル順でアプリと混ぜる。
- `hasShortcutHostPermission()` が false（既定のホームアプリでない）なら、ショートカットは加えない。
- `LauncherApps.Callback.onShortcutsChanged` でも `reload()` する（追加・解除・アプリによる無効化に追従するため）。
- `launch(key)`: `shortcutId` があれば `startShortcut(packageName, shortcutId, null, null, user)`。それ以外は今のまま。失敗（ショートカットが消えた）は何もしない。
- `resolve`・`shortcuts(key)`・`openAppInfo`・`requestUninstall` は、ショートカットの `AppKey` を受けたら何もしないか空を返す。長押しのメニューで出さないので、通常は呼ばれない。
- `allShortcuts()`（検索のための、アプリが公開しているショートカット）は今のまま `FLAG_MATCH_PINNED` を含めない。固定したものは一覧の側に出るので、検索で重複しない。
- 追加: `unpin(key: AppKey)`。同じパッケージの固定したショートカットの id のうち、`key.shortcutId` を除いたものを `pinShortcuts(packageName, 残りの id, user)` に渡す。`AppCatalog` のインターフェースにも追加する。

### アイコン（`LauncherIconLoader`）

- `shortcutId` があれば、`ShortcutQuery().setPackage(pkg).setShortcutIds(listOf(id)).setQueryFlags(FLAG_MATCH_PINNED)` で `ShortcutInfo` を取り、`launcherApps.getShortcutIconDrawable(info, density)` を同じ大きさの Bitmap にする。
- キャッシュのキーに `shortcutId` を含める。

### 追加の依頼を受ける画面

- `:app` に `PinShortcutActivity` を追加する。Manifest で `android.content.pm.action.CONFIRM_PIN_SHORTCUT` を受け、`exported="true"`、ダイアログのように透過した見た目にする。依頼は既定のホームアプリにしか届かない。
- 起動時に `launcherApps.getPinItemRequest(intent)` で依頼を取り出す。`requestType` が `REQUEST_TYPE_SHORTCUT` でない、または `isValid` でなければ閉じる。
- 画面の内容（上から）:
  - ショートカットのアイコンと名前（`shortcutInfo.shortLabel`）
  - 「追加するコマ」の見出しと、コマ割りの縮小図。フォルダのコマだけを押せる（ウィジェットと全アプリ一覧のコマは薄く表示し、押せない）。押したコマを枠で示す
  - 「キャンセル」「追加」のボタン。コマを選ばずに「追加」すると、全アプリ一覧と検索にだけ追加する
- 「追加」で `request.accept()` を呼ぶ。true が返り、コマを選んでいれば `FolderEdits.add(folders, panelId, AppKey(pkg, "", id))` で末尾に入れる。false なら「追加できませんでした」を表示して閉じる。
- 縮小図は、編集画面の縮小図と同じ描き方（`PanelFace` と見本と同じ塗り方）を使う。縮小図のコンポーネントをどのモジュールに置くかは実装に任せる（下の「実装に任せること」）。
- 文言は Android の日本語 UI の慣習に合わせる（例: 見出し「ホーム画面に追加」、ボタン「キャンセル」「追加」）。

```
┌─────────────────────────────┐
│ ホーム画面に追加              │
│ [icon] アイマスイントロ        │
│                             │
│ 追加するコマ                  │
│ ┌──────────────┐            │
│ │   (縮小図)    │  ← フォルダのコマを押して選ぶ
│ └──────────────┘            │
│ コマを選ばないと、アプリの一覧にだけ追加します │
│              [キャンセル] [追加] │
└─────────────────────────────┘
```

### 一覧に無いショートカットの表示（設計者の判断）

今のホームは、フォルダの画面（`FolderPopup.kt` の `appsOf`）とコマのアイコン（`HomeScreen.kt` の `panelIcons`）で、フォルダの中身を一覧と突き合わせずにそのまま描く。一覧に無いアプリは、パッケージ名だけのタイルになる。ショートカットでこれが起きると、ブラウザのパッケージ名のタイルが PWA の数だけ並ぶ。

- ショートカットの `AppKey` のうち、今の一覧（`AppCatalog.apps`）に無いものは、表示するときに隠す。フォルダのデータには残す。対象は、別の端末に復元したとき、ブラウザの側で PWA を消したとき、ブラウザをアンインストールしたとき。
- 隠した後の並びを、フォルダの画面・コマのアイコンの数・直接起動の先頭・フォルダの中の並べ替えの位置の全てで使う。並べ替えの位置は、隠した後の並びの位置を、データの中の位置に直してから `FolderEdits.reorder` に渡す。
- 消えたショートカットをフォルダのデータから外す処理は作らない。ロックの解除前や既定のホームアプリでない間は、ショートカットを一時的に取得できない。そのときに消えたと判断すると、利用者の割り当てを壊すため。
- アプリ（`shortcutId` が null）の扱いは今のまま変えない。

### 長押しのメニュー（`HomeOverlays.kt` の `AppMenu`）

- `menu.app.shortcutId != null` のとき、「アプリ情報」と「アンインストール」を出さず、「削除」（赤）を出す。押すと確認のダイアログ（例: 「アイマスイントロを削除しますか。」と「キャンセル」「削除」）を出す。固定の解除はランチャーから戻せず、ブラウザで追加し直すしかないため（利用者が確認を選んだ）。「削除」で `AppCatalog.unpin` を呼び、全てのフォルダから外す（`FolderEdits.remove` を各コマに）。ダイアログはホームの `Overlay` に追加する。
- アプリのショートカット一覧（`menu.shortcuts`）は空なので出ない。
- 全アプリ一覧の長押しのメニューが同じコンポーネントなら、同じ扱いになる。別のコンポーネントなら、同じ分岐を入れる。

### バックアップ

`koma-launcher-backup.json` のフォルダの中身には、ショートカットの `AppKey` もそのまま入る。別の端末に復元しても、固定は Android の側の状態なので戻らない。一覧に無いショートカットは隠すので、表示されない（上の「一覧に無いショートカットの表示」）。README の「機種変更のときは次の順に戻せる」に、PWA は追加し直す必要があることを書く。

### 確かめる方法

- 単体テスト（`:core:model`）
  - `shortcutId` の無い既存の `folders.json` の JSON が読めること、ショートカットの `AppKey` が往復すること
  - `Launches` の id がショートカットで `パッケージ/@id` になり、`asMap` で戻ること
  - `FolderEdits` の add・remove・reorder が、同じパッケージのアプリとショートカットを別のものとして扱うこと
- Waydroid
  - debug ビルドに、自分自身のショートカットの固定を依頼する受け口（`DEBUG_PIN`）を追加し、依頼を受ける画面・追加・一覧への表示・フォルダへの追加・起動・削除を確かめる。e2e に項目を追加するかは実装に任せる
- 実機（利用者の POCO X7 Pro）
  - Vivaldi でアイマスイントロアプリと paper-catch-up を追加し、コマから起動したときにタブではなく PWA の画面（アドレスバーの無い画面）で開くこと
  - 削除すると一覧とフォルダから消えること

## 実装に任せること

次の点は設計者が決めた。実装で守る。

- 全アプリ一覧（`DrawerScreen.kt`）とアプリを選ぶ画面（`AppPicker.kt`）の一覧の key は今 `パッケージ/クラス` で、同じブラウザの PWA が重なる。`shortcutId` を key に含める。
- 検索で、アプリのショートカットの行の持ち主のアプリを `packageName` で引く処理（`appOf = visible.associateBy { it.key.packageName }`）は、固定したショートカットの項目を除いたアプリだけから引く。
- 一覧から自分のパッケージを除く処理は Activity にだけ掛け、固定したショートカットには掛けない（`DEBUG_PIN` で固定した自分のショートカットを表示するため）。

次の点は実装に任せる。

- 縮小図のコンポーネントをどのモジュールに置くか。編集画面（`:feature:editor`）の縮小図の描き方を共有できるなら `:core:ui` に移してよい。依存の向き（README の「構成」）は守る。
- 依頼を受ける画面の細かい見た目（大きさ、余白、選んだコマの示し方）。
- 検索で、ショートカットにパッケージ名（例: `vivaldi`）での一致をさせるかどうか。今の照合のままだと、「vivaldi」と打つと Vivaldi で追加した全ての PWA が候補に並ぶ。名前での一致より下に並ぶので、そのままでもよい。
- `DEBUG_PIN` の作り方と、e2e に項目を追加するかどうか。
