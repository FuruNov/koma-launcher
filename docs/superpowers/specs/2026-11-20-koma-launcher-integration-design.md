# koma-launcher 組み込みの計画（11/20 にモックアップで決めた内容をアプリへ）

## Context

一晩目（11/19）に作ったアプリは、「1 枚の絵をコマの形で切り抜く」方式のホーム画面、フォルダ、全アプリ一覧、ドラッグでの編集、ウィジェット、設定画面までを持つ。11/20 の朝に、利用者と HTML のモックアップ（claude.ai の Artifact、保存は db の `editor/current`）で次のことを決めたが、アプリにはまだ入っていない。見た目を先にモックアップで決め、固まってから組み込む方針だったため。

決まったこと（モックアップに実装済みで、計算の式もそこにある）:

- コマ割りはランチャー内の GUI で編集する。方式は「線で割る」（コマを選んで横・縦に割り、線の端をコマの縁に沿って動かして斜めにする、線を消して戻す、元に戻す）。最初の形は大ゴマと 1 コマの 2 つだけ（4 コマ・斜め割りは不要と利用者が判断）
- コマごとに別の画像。位置と拡大率はドラッグとピンチで合わせる。絵の端は見せない（拡大率の下限 1、動かせる範囲を制限、形が変わるたびに収め直す）
- コマの種類はフォルダ・ウィジェット・全アプリ一覧（「その他」のコマに割り当てる）
- フチ: 枠線の太さ、1 本線・二重、裁ち落とし。コマの間の幅と色
- 漫画風の変換は「淡い色合い」だけ（細部を損なわず、色合いだけを変える）＋かかり具合
- 陰影: 内側の影と光の反射（光は傾きと逆へ流れる）
- 時計はランチャー自身が描き、「人物の後ろ」に回り込ませる（数字を人物の形を抜いた切り抜きで切る）
- 文字: 大見出し（Bodoni 斜体、幅をコマの 9 割に合わせる）と、コマの名前（英語が既定、縦書き・横書き、人物の地図で隠れにくい位置をコマ全体から探す、常に人物の後ろ）
- 視差: 絵（背景と人物を一緒に）と、文字・時計を別の速さで動かす。集中線は外す
- ロック解除は「にゅっと滑り込む」、タップは「沈んで弾む」（実装済み）
- 切り抜きは BiRefNet が最良（PC）。端末では未確認

あわせて、11/20 の撮影で見つけた不具合を直す: ウィジェットがコマの内接長方形を覆うと、ウィジェットが長押しを受け取ってしまい、コマのメニュー（ウィジェットを選ぶ・外す）が開かない。

## 進め方

- koma-launcher のディレクトリ（`~/ghq/github.com/FuruNov/koma-launcher`）で新しいセッションを開いて進める。設計の文書（`docs/superpowers/specs/`）に今日の決定を追記してから、段階ごとに実装計画を書く
- 段階ごとに、Waydroid（1220×2712 を再現）で動かしてスクリーンショットを見せ、次へ進む。段階の終わりに Sonnet のサブエージェント 1 体にレビューを頼む
- 画像と切り抜きはリポジトリに入れない。端末へは adb で送る

## 段階

### 0. 後片付け（最初に 1 回）
- Waydroid: `wm size reset`、`wm density reset`、ホームを Launcher3 に戻す（11/20 の撮影の名残）

### 1. コマ割りの木とコマごとの画像（土台）
- `:core:model`: 線の木（`LayoutNode` = 葉 `Leaf(panel)` / 枝 `Split(ta, tb, a, b)`、ta・tb は親の周に対する割合）。凸多角形の半平面での切り抜き、`pointAt`・`paramOf`、コマの間の幅、外周の余白と裁ち落とし。モックアップの `layout()`・`clip()`・`pointAt()`・`paramOf()` を Kotlin に移す
- `PanelContent` に `Drawer` を加える。コマごとの `PanelArt(imageId, zoom, dx, dy)` と、端を見せないための `ArtLimits`（モックアップの `artLimits()`・`clampArt()`）
- layout.json を version 2 にする（木・フチ・コマの間・画像の参照）。version 1（平らな多角形）は読み込めるようにし、編集画面では型から始め直す
- レイアウトはアプリが持つ（内部の `layout.json` を `JsonFileStore` で保存）。adb で送る外部の layout.json は「取り込み」として扱う
- 画像は内部の `files/art/<id>.webp`（長辺 2048 以下に縮めて保存）。描画は既存の `PanelLayer` を、コマごとの画像を cover＋拡大率＋ずらしで描く形に変える
- モックアップの保存状態を取り込む開発用のスクリプト（`scripts/import-mockup.sh`: db の state と手元の画像から v2 の layout.json を作り、adb で送る）。これで利用者が作ったコマ割りと画像を、そのままアプリで再現する
- ウィジェットの長押しの不具合を直す（ウィジェットの上でも、ランチャーが長押しを受け取る）
- 全アプリ一覧のコマ（押すと全アプリ一覧を開く）

### 2. 編集画面（線で割る）
- 新しいモジュール `:feature:editor`。ホームのメニューの「コマ割りを編集」から入る
- 型の選択（大ゴマ・1 コマ）、コマの選択、横・縦に割る、線の端のドラッグ（親の縁に沿う）、線を消す、種類の切り替え、元に戻す、コマの間の幅と色、裁ち落とし、枠の種類と太さ
- 画像の選択は Android の写真の選択画面（権限不要）。選んだ画像を縮めて内部へ写す。ドラッグとピンチで位置と拡大率を合わせる（端を見せない制限つき）
- 編集の操作は `:core:model` の純粋な関数にし、テストする（割る・消す・元に戻す・id の引き継ぎ）

### 3. 見た目（フチ・色合い・陰影）
- 枠線（内側に引く、二重）、淡い色合い（ColorMatrix。かかり具合で混ぜる）、内側の影、光の反射
- Compose の `drawWithCache` で、コマの形が変わったときだけ作り直す

### 4. 切り抜きと文字（人物の後ろ）
- 切り抜きは端末の中で ML Kit の被写体の切り抜きで作り、PC で作った切り抜き（BiRefNet）を取り込む方法も用意する。濃さ 0.35〜0.65 を 0〜1 に詰め、反転して使う
- 時計（ランチャーが描く「人物の後ろ」）、大見出し、コマの名前（英語の対応表、縦・横、人物の地図で位置を探す）。書体は Dela Gothic One と Bodoni Moda（どちらも OFL）をアプリに同梱する
- 名前の置き場所の探索（3 段階の大きさ × 7×7）は純粋な関数にしてテストする

### 5. 視差
- 端末の傾き（game rotation vector）を、ホームが見えている間だけ読む。1 度未満は無視し、ゆっくり追従させる
- 絵（背景と人物）・文字・時計を別の量で動かし、絵は動く分だけ大きく置く。光の反射も流す

## 再現の難しさ（11/20 に利用者へ説明）

- 容易: コマごとの画像、線の木の計算、フチ、淡い色合い（ColorMatrix で正確に表せる）、光の反射、人物の後ろの文字（別の層に描いて BlendMode で抜く）、書体と縦書き、視差。モックアップの計算を素の式で書いてあるので、Kotlin へそのまま移す
- 中くらい: 編集画面の指の操作の感触の調整、内側の影（ぼかしの描き方が SVG と違うので、グラデーションで近づける）
- 不確か: 端末の中での人物の切り抜き。ML Kit の品質を段階 4 の最初に試し、足りなければ PC（BiRefNet）で作った切り抜きを画像と一緒に送る方法にする
- 文字やぼかしの細部は、ブラウザと Android でわずかに違う。並べて見比べて、気になる所を合わせる

## 検証

- 各段階で `nix develop -c ./gradlew spotlessApply lint testDebugUnitTest assembleDebug assembleRelease`
- `:core:model` のテスト: 木の切り抜き（割る・消す・線を動かす・幅を変える）、v1 から v2 への読み込み、端を見せない制限（モックアップの 10 の場面と同じ）、名前の位置の探索
- Waydroid（1220×2712 を再現）: e2e スクリプトに編集画面の操作を加える。モックアップの保存状態を取り込んだ画面と、モックアップの画面を並べて見比べる
- メモリ（11/20 に要件を改めた。100 MB は根拠のない目安だったため）:
  - 実機で、POCO X7 Pro の標準のホームアプリと同程度以下（実機で両方を `dumpsys meminfo` で測って比べる）
  - 長時間の使用や、画像の取り込み・編集の繰り返しで、使用量が増え続けない（`scripts/measure.sh` を編集の操作の前後で比べる）
  - ホームが裏に回ったら、アイコンなどのキャッシュを手放す（実装済みの `onTrimMemory` を、コマの画像の扱いにも広げる）
  - コマごとの画像は表示の大きさで読み、GPU 側に置く（画像の合計は画面 1 枚分、約 13 MB の見込み）
- 実機（POCO X7 Pro）で後から確かめる: ML Kit の切り抜きの品質、傾きのセンサー、HyperOS のジェスチャー、ロック解除の通知
